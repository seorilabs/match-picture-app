# MP-IOS-116 검증 단계와 인수조건 연결

승인 설계 v1의 AC-1~AC-4는 그대로 유지한다. 구현·Editor 검수, 빌드·TestFlight 도달, 네이티브 기기 검수, 심사·공개 확인은 서로 다른 단계다. 현재 이 문서는 연결 기준이며 최종 E2E나 실기기 통과 기록이 아니다.

[중앙 개발 절차](https://github.com/seorilabs/.github/blob/main/docs/agent-governance/development-workflow.md#빌드-직전과-배포-직전-e2e)는 Editor에서 확인할 수 없는 네이티브 광고·권한의 플랫폼 실기기 근거를 따로 요구한다. [승인 설계](../../design/2026-10-11-ios-1.1.6-stability/design.md#적용출시복구)는 최종 Editor E2E·중앙 검증 이후 App Store 빌드·업로드, TestFlight iPhone/iPad 실제 SDK 검수를 실행하는 순서다. 아직 만들어지지 않은 네이티브 산출물의 결과를 빌드 전 Editor 결과에 넣지 않는다.

| 원래 인수조건 | 개발 단계에서 실제 검증할 범위 | 최종 출시 조건으로 남는 범위 |
|---|---|---|
| AC-1 | 단일 저장·실패 반환/이전 메모리·파일/백업 보존의 테스트, 실제 정상 main 완주/파일 재시작/손상 복구, 실제 실패 결과 안내 | TestFlight의 기존 기록·완주·재시작 및 네이티브 화면 확인 |
| AC-2 | 광고 대역의 최초 실패→다음 판 완료 준비·중복/오래된 콜백 차단, 실제 Retry가 게임 진행을 막지 않음 | 해당 TestFlight 빌드의 실제 테스트 광고·실패 뒤 복구·재시도 진행 |
| AC-3 | 실제 시작/결과 설정과 한국어·영어·소리, 대역의 필요/늦은 상태·열기 중 중복·실패/완료 콜백과 오류 안내 | iPhone/iPad 실제 UMP 필요 여부·양식·동의 변경·취소/실패와 광고 흐름 |
| AC-4 | 플랫폼·이벤트 대역의 정확한 시장/제공자/REQUESTED·SKIPPED 값, 허용 파라미터 회귀, 실제 desktop 미지원 분기 | 네이티브 기기 로그·실제 제공자와 전송 확인 |

빌드 전 증거의 개발 단계 항목은 각각 `AC-1/development`~`AC-4/development`로 연결하고, 원래 인수조건을 별도의 최종 출시 체크리스트로 보존한다. 이 접미사는 통과 범위를 명시하는 단계 식별자이며 네이티브 검수 면제나 원래 조건의 축소가 아니다. 각 개발 항목도 실제 요구사항 실패 테스트·통과 로그·독립 UI 및 최종 E2E 근거가 있어야 통과로 기록한다. 통과하지 않았거나 실행하지 않은 항목의 허용용 JSON은 만들지 않는다.

`docs/qa/feature-inventory.json`의 **13개 구현 기능 모두**를 유지하고 최종 Editor E2E 시나리오에 연결한다. desktop에서 지원하지 않는 Game Center·광고/UMP·AIT 공유·계측은 실제 미지원 버튼 숨김/no-op·게임 진행과 SDK 대역을 구분해 기록한다. 대역 콜백이나 숨김 통과를 실제 SDK 성공·광고 노출·네이티브 안전영역/화면 유지·하드웨어 Back·프로덕션 전송으로 표시하지 않는다. 지원 플랫폼에서의 실제 검증은 최종 출시 조건으로 남는다.

최종 E2E JSON은 소스 SHA를 바꾸지 않도록 소스 밖에서 작성하고 해당 태그의 GitHub Release 자산으로 보존한다. 같은 SHA·App Store 대상·설정 지문·전체 기능 목록의 결과만 중앙 검증에 사용한다. 기존 UI 실패·미검수 결과를 지우거나 최종 E2E로 추가 UI 회차를 우회하지 않는다.
