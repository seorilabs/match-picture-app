# 교차 리뷰 처리

1차 로컬 Claude 읽기 전용 리뷰 대상은 `36706599aa9c9101879933de79b7351204f9af04`이다. [원문 댓글](https://github.com/seorilabs/match-picture-app/pull/111#issuecomment-6109019712)을 편집하지 않고 게시했다. P1 없음, P2 한 건과 P3 세 건을 다음처럼 처리한다.

1. **수용**: 초기 UMP 정보 갱신과 사용자 개인정보 양식 열기를 구분한다. 정보 갱신 동안 중복 요청 차단을 유지하되 `여는 중`은 실제 사용자 양식 요청에만 표시한다. 포트가 두 상태를 따로 알려 주므로 버튼을 조기 활성화하지 않는다.
2. **수용**: 양식 요청이 거절되면 최신 필요 상태를 다시 반영한다. REQUIRED가 사라졌는데 버튼만 남는 상태를 없앤다.
3. **부분 수용**: Godot 4.7.2 `store_buffer()`는 쓰기 오류를 검사하지만 `flush()`는 오류 상태를 갱신하지 않는다. [실제 엔진 소스](https://github.com/godotengine/godot/blob/4.7.2-stable/drivers/unix/file_access_unix.cpp)를 확인했다. 쓰기 반환값·오류 상태·실제 파일의 UTF-8 바이트 길이를 모두 확인한 후에만 파일을 회전·승격한다. 부분 쓰기가 성공으로 보고되는 저장 대역을 사용해 실제 임시 파일이 짧은 경우 이전 정본을 보존하는 회귀를 추가했다. 실기기의 디스크 부족을 재현했다고 표시하지 않는다.
4. **소명**: 캡처 도구의 메모리 저장은 실제 사용자 기록을 보호하기 위한 격리다. 새 사용자의 기록 없는 타이틀도 실제 제품 상태다. 임의 최고 기록을 마켓 이미지에 추가하는 변경은 하지 않는다. 제출용 이미지는 최종 iOS 후보의 실제 화면으로 별도로 검수한다.

추가 회귀는 변경 전 59개 검사 중 요구사항 실패 4건을 확인했다([실패 로그](tdd-review-red.txt)). 수정 후 59개 회귀와 전체 `npm run check`가 통과했다. 전체 assertion은 302개이며 실제 UI·UMP·광고·실기기 통과를 의미하지 않는다.

수용한 수정이 새 분기와 메서드를 만들었으므로 2차 리뷰는 이 1차 SHA 이후의 수정분만 확인한다. PR당 요청은 실패 포함 최대 2회이며 2차 뒤 반복하지 않는다.
