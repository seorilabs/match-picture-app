# 추가 UI 검수 1회 제안 — 승인 전 미실행

설계 MP-IOS-116 v1, 실행 티켓 #110, PR #111의 기존 기능 검수를 마무리하기 위한 제안이다. **사용자 승인 없음 / 4회차 시작하지 않음**. 코드·게임 규칙·SDK·데이터 형식 변경을 제안하지 않는다.

## 이유와 현재 근거

1회차는 초기 QA 조립 오류 수정 뒤 실제 실행·입력이 차단됐다. 2회차는 격리 메모리 저장과 SDK 대역의 실제 Editor Run·설정·게임·정상/실패 결과를 확인했다. 3회차의 embedded 정상 main은 최초 창 0 크기에서 카드/HUD 미표시와 11개 런타임 오류가 발생했다. 독립 창의 다음 정상 main은 실제 engine rect/transform이 유한하고 오류가 없었지만, 같은 bundle의 Editor/게임 두 프로세스를 CUA가 구분하지 못해 입력이 차단됐다. 각각의 원래 실패·미검증 결과를 보존한다.

3회차 마지막 Run은 headless Editor가 공식 play_main_scene로 실행한 실제 GUI 게임만 정확히 식별해 독립 입력 검수를 완료했다. 540×720에서 정상 최초 안내·10정답·9개 측정 구간·최고82.887165초·완료1·설정·Retry·취소/Yes를 확인했고 primary/.bak에 동일한 기록이 있다. [최종 보고서](iteration-3.md)와 [실제 증거](evidence/round-3/final-evidence-manifest.json)를 보존했다. 정상 파일을 이용한 재시작 보존, 손상 primary의 정상 .bak 복구, 정상 main의 좁은 화면 입력·전체 화면비는 미검증이다. 원인 조사나 넓은 창의 성공만으로 기존 실패를 환경 문제나 해결 완료로 바꾸지 않는다.

## 승인 요청 범위

- 추가 **UI 1회차(4회차)만**, **실제 Editor Run 최대 3회**, 약 **30~40분**. 검수자 `/root/ui_review`, 구현자 `/root`와 분리한다. 새 유료 서비스·계정·장비를 생성하지 않고 기존 도구를 사용한다.
- 제품 후보는 문서 정리·CI 후 확정한 PR HEAD로 고정한다. 승인·후보·격리 설정·계획·시작/종료 시각·증거를 실제 실행 전에 기록한다.
- 전용 프로젝트·game userdir·Editor config/cache·고유 QA 앱을 사용한다. 다른 Godot·사용자 저장·앱·계정·시뮬레이터를 변경하지 않는다.
- 도구가 실제 GUI 게임만 정확히 식별할 수 있는 Editor Run 구성을 확인한 뒤 입력한다. headless Editor가 GUI child를 공식 play_main_scene로 실행한다면 두 모드를 명확히 기록하고, 실제 제품 GUI 렌더/입력을 증명한다. child GUI를 확인할 수 없으면 미검증으로 중단한다.
- core 기능 9개 전체의 기능·UX를 확인한다. desktop 미지원 순위·광고·공유·계측은 실제 숨김/no-op 상태만 확인하며 네이티브 UMP·광고·실기기 통과를 주장하지 않는다.

PNG/실제창의 관찰 치수를 기록한다. Retina의 1픽셀 차이는 요청값과 관찰값을 구분하고 종횡비·레이아웃을 실제 값으로 검토한다. 소스/에셋 일치와 환경만의 diff/hash를 남긴다. 저장 실패/조건부 개인정보 오류 대역의 기존 2회차 증거는 별도 연결하며 정상 파일 재시작 증거로 재사용하지 않는다.

## 상한·중단 영향

한 회차 안에서 추가 실행을 무제한 반복하지 않는다. 3회 실행 또는 40분을 넘기기 전 완료하지 못하면 결과를 그대로 남기고 중단한다. 5회차는 별도 승인 없이는 시작하지 않는다. 이 추가 회차가 승인되지 않거나 필수 기능/UX가 통과하지 않으면 PR 병합·빌드·업로드·심사 제출이 차단된다.

UI 마지막 회차 통과 뒤 최종 SHA의 전체 기능 E2E와 중앙 검증은 이미 승인된 출시 절차에서 별도로 진행한다. iPhone/iPad TestFlight·실제 SDK·마켓 문구/이미지·개인정보 read-back·심사·공개/live 단계도 별도다. 이 제안으로 출시 검수를 통과 처리하거나 예외를 승인받았다고 하지 않는다.

정본: [개발 계약 실행 문서](https://github.com/seorilabs/.github/blob/main/docs/agent-governance/development-workflow.md#ui-검수-3회)의 “승인 전에 4회차를 시작하지 않는다.” 조건에 따라 사람 승인 후에만 실행한다.
